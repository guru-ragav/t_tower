Game Rules & Computer Science Architecture

Comprehensive documentation of gameplay rules, physical equilibrium mechanics, and Python data structure implementations.

1. Tumble Tower Rules

Official tournament constraints governing block extractions and tower apex construction.

Rule 1 • Two-Step Turn: On their turn, the active player must extract exactly one accessible block from the tower and place it on top of the tower before the turn rotates.
Rule 2 • Foundation Protection: Blocks on Level 1 (the base level) cannot be removed. They anchor the entire structure to the pedestal.
Rule 3 • Top Levels Protection: Blocks located in the topmost incomplete level (where blocks are actively being placed) or in the top three complete levels cannot be extracted. Blocks must be taken from below these protected levels.
Rule 4 • Anti-Hollowing Protection: You cannot remove the last remaining block on any level, as doing so leaves zero physical support for all upper layers.
Rule 5 • Apex Placement: An extracted block must be placed onto the highest level. Levels fill with 3 blocks in alternating orientations (horizontal on odd levels, vertical on even levels). Once a 3-block layer is complete, a new layer begins.
Rule 6 • Collapse & Victory Condition: If a move causes the center-of-mass to exceed the support base polygon, the tower collapses! The player whose move triggered the collapse loses, and the immediately preceding player in the FIFO queue is crowned the winner!

2. Data Structures & Algorithms Implementation

Detailed breakdown of native Python classes engineered for this application.

A. Stack Class (LIFO – Last-In, First-Out)

stack.py

Implemented methods: push(), pop(), peek(), is_empty(), size(), display().

  • Auxiliary Block Storage: When a player extracts a block from Level L, all overhead blocks from levels > L are popped and pushed onto an auxiliary stack. Once the target block is extracted, the auxiliary stack pops and restores each block back into its exact original position in reverse order (LIFO).
  • Multi-Step Undo Engine: Every committed move pushes a complete system state snapshot onto HistoryStack. Pressing "Undo" pops the top snapshot, restoring the previous tower arrangement, block locations, player turns, and stability metrics.

B. Queue Class (FIFO – First-In, First-Out)

queue.py

Implemented methods: enqueue(), dequeue(), peek(), is_empty(), rotate(), rotate_backward().

  • Round-Robin Turn Scheduling: At match launch, players are enqueued. The active contestant is at the front (peek()). When their turn concludes with block placement, rotate() dequeues them from the front and appends them to the rear of the queue.
  • Undo Turn Synchronization: When an undo operation occurs, rotate_backward() shifts the rear contestant back to the front, seamlessly restoring the previous player's turn.

C. Linked List Class (Doubly Linked Layer Hierarchy)

linked_list.py

Implemented classes: LevelNode, LinkedList. Methods: insert_level(), insert_block(), delete_block(), traverse(), display().

  • Dynamic Vertical Growth: Each node represents one horizontal or vertical floor containing 3 block slots [0, 1, 2]. As the tower grows past 18 levels, new nodes are dynamically appended to the tail.
  • Bidirectional Traversal: Traversal from tail to head enables top-down rendering in HTML/CSS, while bottom-up traversal calculates physical center-of-gravity load distributions.

D. Block Searching Algorithms

game_engine.py

Supports multi-criteria searching by Block ID, integer number, natural wood grain colour, and level number. Recursively navigates the tower's linked list and held block buffers to report exact 3D coordinates, orientation, accessibility, and status reasons.
